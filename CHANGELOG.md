# Changelog

All notable changes to this project will be documented in this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.3.0] - 2026-11-13

### Added
- **Set-of-Mark UI Element Detection (`marks: true`)**: `handy_see` and `handy see --marks` now detect, classify, number, and outline the interactive elements on screen instead of leaving an agent to guess coordinates from pixels. A new `src/marks.ts` runs edge detection, morphological dilation, and connected-component labelling over a DPI-normalised work buffer, classifies each component as `control`, `text`, `icon`, or `region`, scores it by edge density, fill contrast against its surround, and solidity, then merges adjacent glyph fragments into whole text lines. Marks are numbered `1..N` in reading order and returned as `elements` with `index`, `kind`, bounds, `centerX`/`centerY`, and `score`. Detection is DPI-independent (~18ms at 1280x800, ~22ms at 2560x1440, ~49ms at 4K) because the work buffer is area-capped rather than dimension-capped.
- **Click-by-Mark Everywhere**: Every pointer step — `move`, `click`, `double_click`, `triple_click`, `right_click`, `drag` (both endpoints, via `fromMark`/`toMark`), and `scroll` — accepts `{ "mark": N }` in place of `{ "x": …, "y": … }`. Marks resolve to the element's own centre at execution time, so a chain keeps working if the layout shifts between capture and action. Out-of-range marks, and marks referenced before any marked capture, fail with an error listing the available indices rather than clicking somewhere arbitrary.
- **Mark References in the Chain DSL**: `click mark 5`, `click #5`, `move mark 3`, `drag mark 3 mark 7`, `drag mark 3 300 400`, and `scroll down 4 mark 9` now parse in `handy act '<chain>'`, the Control Panel chain runner, and everywhere else the text DSL is accepted. Pre-existing coordinate forms (`click 400 300`, `click 400,300`, `drag x1 y1 x2 y2`, `drag x2 y2`, `scroll 5 10`) parse exactly as before.
- **Human-Like Pointer Motion (`motion: "linear" | "ease" | "human"`)**: `move` steps can travel a Bézier arc with eased timing instead of a straight constant-speed interpolation. `"human"` derives its duration automatically from a Fitts's-law model of travel distance and target width (clamped 0–1200ms) when `durationMs` is omitted, so a long move to a small target takes visibly longer than a short move to a large one.
- **Post-Action Verification (`verifyChange: true`)**: `handy_act` can capture a baseline before the chain and report `changed` plus a `change` frame diff afterwards, giving a cheap post-condition check that catches clicks which landed but did nothing.
- **Control Panel Mark Support (`handy ui`)**: A new "Detect Marks" toggle drives `/api/see?marks=1`, a "Detected Marks" card lists every element with its bounds and score on hover (clicking a row appends `click mark N` to the chain input), telemetry gains a UI Elements row, and clicking an element directly on the screenshot now inserts its mark reference instead of raw coordinates — resolving to the tightest containing element so nested controls pick the innermost target.
- **PNG Row-Filter Selection (`filter: "auto" | "none" | "sub" | "up" | "paeth"`)**: `encodePng` picks Paeth for the first row and for rows that differ from their predecessor, and Up for rows identical to the one above — which is most rows in UI captures. End-to-end `see()` PNGs are ~26% smaller (53KB → 39KB at 2560x1440) at no measurable encoding cost. An exhaustive per-row filter search was evaluated and rejected: ~3x slower for ~4% smaller.
- **Fail-Soft Element Detection (`marksError`)**: Detection is an enhancement layered on a capture, not the deliverable, so a detector failure now degrades to a plain screenshot instead of failing `handy_see` outright — the agent keeps the capture it actually needs. The reason is reported in `SeeResult.marksError`, surfaced through `handy_see` metadata with a hint to fall back to ruler coordinates, and printed by `handy see --marks`. Marks from an earlier successful capture are cleared at the same time, so a later `click mark N` cannot resolve against a stale layout and silently hit the wrong control.
- **`pickDisplay` Helper (exported)**: Resolves a display by `id`, falling back to positional index and then to the primary display. Replaces six subtly divergent copies of `displays.find((d) => d.id === (displayIndex ?? 0)) ?? displays[0]` across `controller.ts`, `darwin.ts`, `linux-x11.ts`, and `win32.ts`.
- **Backend Capability Flag (`nativeClickCount`)**: `DesktopBackend` gains an optional `readonly nativeClickCount?: boolean`. `DarwinBackend` sets it, and the controller branches on the flag instead of `instanceof DarwinBackend`, so any future backend that can carry a click count and held modifiers on the native event opts in without the controller importing it.

### Changed
- **Area-Average Downscaling**: `resizeRgba` now box-filters with exact coverage weighting when downscaling, with an unrolled fast path for integer ratios. This is a quality fix, not just a speed one: bilinear sampling lands *between* 1px features and erases them, so a 3x downscale of text lines drifted 37.5 luminance units from the source while box filtering drifts 0.00 — the text simply vanished. Box filtering also runs ~3x faster (32.9ms → 10.4ms for 2560x1440 → 1280x720). Bilinear remains available via `{ filter: "bilinear" }` and is still used for upscaling.
- **Faster Frame Diffing**: `computeFrameDiff` compares whole RGBA pixels as single 32-bit words, skipping unchanged pixels with one integer comparison (18.5ms → 8.0ms for identical 1440p frames). It accepts a `FrameDiffOptions` object with `earlyExitPercent` (stop scanning once the verdict is known, returning `partial: true`) and `computeBounds` (skip changed-pixel bounds when only the percentage is needed); the legacy numeric channel-delta argument is still accepted. Unaligned buffers fall back to a byte-wise scan that is verified pixel-for-pixel identical to the fast path.
- **Smarter Visual Wait Polling**: `wait_for_change` and `wait_for_settled` poll with `{ earlyExitPercent: threshold, computeBounds: false }`, so on an actively animating screen each poll bails out at `threshold`% of pixels instead of scanning the full frame and computing bounds it never reads. `wait_for_change` reports `>= N%` when its scan short-circuited rather than paying for a second full capture to refine a number that is already a yes.
- **`wait_for_settled` Threshold Semantics**: "Quiet" now means *strictly below* `threshold` percent rather than at-or-below, which makes the early exit provably equivalent (`earlyExitPercent === threshold` means a `partial` diff implies `changedPercent >= threshold`, i.e. not quiet). The schema description is updated to match, as is the previously undocumented `0.1` default.
- **Strict Chain-DSL Argument Validation**: Malformed pointer arguments now throw with the offending segment quoted instead of silently degrading to "act wherever the cursor happens to be". Previously `click mark 5` parsed as a bare click and reported success while clicking somewhere arbitrary, `click 12` (one coordinate) did the same, and `drag 100 200 300` discarded the trailing argument. Trailing arguments and out-of-range mark indices are rejected too.
- **Element Classification Keys on Height, Not Interior Variance**: `classifyKind` decided control versus region with `stddev < 70 ? "control" : "region"`, which conflated two unrelated things — a gradient-filled CTA carrying a white label has a bimodal, high-variance interior just like a panel full of text, so the most common button style in modern UIs was filed as a region and the agent lost the signal that it was clickable. Height is the real discriminator: `height <= 120 && area <= 90_000` is a control, with a narrow escape hatch for oversized solid tiles.
- **Button Captions No Longer Get Their Own Mark**: IoU dedup could not catch a label inside its button (a 171x19 caption in a 226x54 button has IoU ~0.27, under the 0.5 cutoff), so every labelled button spent two marks and invited a click on the text rather than the control. A containment pass now drops `text`/`icon` marks that are >=80% covered by a `control`. Controls and regions are never suppressed — nested controls are real, and panels legitimately hold many independent text lines.

### Fixed
- **Typecheck Was Broken**: `npm run typecheck` failed with 281 errors because `tsconfig.json` did not declare `"types": ["node"]`, and TypeScript 7 no longer auto-loads `@types` packages. Every `Buffer`, `process`, `node:fs`, `NodeJS`, `AbortSignal`, `URL`, and `setTimeout` reference in the codebase was unresolved. Tests passed regardless because Vitest does not typecheck, so CI was green while the build was not.
- **Overlay Badge Clipping**: Mark badges and other overlay text are now clamped to the canvas bounds, so an element at any corner renders its full badge instead of being cut off.
- **Dead Code**: Removed `normalizeDiffOptions` (unused, and carrying a bogus `as never` cast) along with `cropPixels`/`downsamplePixels`, superseded by `chooseWorkSize` plus the shared `cropRgba`/`resizeRgba` from `png.ts`.

### Tests
- **Test Typechecking (`tsconfig.test.json`)**: `tsconfig.json` only included `src/**/*.ts` and Vitest does not typecheck, so every test file had zero type coverage. `npm run typecheck` now runs both the emit-accurate src config and a `noEmit` config covering `src`, `tests`, and `scripts` (with `typecheck:src` / `typecheck:tests` available separately), so the existing CI step covers it with no workflow change. Wiring this up immediately surfaced 11 real errors: `scripts/validate-release.ts` could not construct `Ajv` or call `addFormats` (both ship CJS with `__esModule`, which NodeNext types as a non-constructable module namespace even though `module.exports` really is the class at runtime), a test passed `updatedBy: "cli-test"` outside the closed `"cli" | "mcp" | "ui"` contract, `mock-x11-server.ts` inferred `Buffer<ArrayBuffer>` from `alloc()` and then rejected `ArrayBufferLike` socket chunks, and test helpers broke under `noUncheckedIndexedAccess`. All fixed — including widening `VirtualDesktopBackend.mouseDown`/`mouseUp` to mirror the interface signature, which a two-parameter test spy exposed.
- **Artifact Drift Check in CI**: A post-build step fails when `lib/`, `bin/`, or `public/` differ from what a fresh build produces. Safe rather than flaky because the build is byte-for-byte deterministic (two consecutive builds give identical checksums and a clean tree) and `.gitattributes` pins `* text=auto eol=lf` plus `*.png binary`, so the Windows runner cannot report CRLF noise.
- **56 new tests — 40 → 96 passing (41 → 97 total, 1 skipped)** across four files. `tests/v1-3-features.test.ts` (42) covers box-filter energy conservation versus bilinear text erasure, the integer fast path, lossless round-trips for all five PNG filter strategies, fast-path/fallback diff equivalence on 1-byte-offset buffers, alpha-only and legacy-threshold diff behaviour, `earlyExitPercent`/`computeBounds`, mark detection accuracy and ordering on synthetic and virtual-desktop frames, HiDPI logical mapping, frame-origin offsets for window captures, `maxMarks`/`kinds`/`minScore`/`searchRegion`, photographic-noise and degenerate-frame safety, corner badge rendering, click/type/submit/scroll/drag by mark, every mark rejection path, Fitts's-law clamping, linear-versus-bowed trajectory deviation, `nativeClickCount` capability detection, `pickDisplay` fallback, and every chain-DSL mark and coordinate form. `tests/marks-realistic.test.ts` (9) covers UI styles the synthetic light desktop never produces — dark theme with hairline borders, gradient-filled rounded cards with drop shadows, borderless flat links, dense icon toolbars — plus caption suppression in both score orderings and its negative cases. `tests/marks-failsoft.test.ts` (4) forces the detector to throw via a `vi.hoisted` mock switch and asserts the capture survives, the reason is reported, detection recovers on the next call, and stale marks are cleared so they cannot be clicked. `tests/mcp-stdio.test.ts` gains an end-to-end test over a real child-process MCP server, and two tests drive the Control Panel over real HTTP on loopback.

## [1.2.0] - 2026-11-12

### Added
- **Window-Scoped Screen Capture (`window`)**: `handy_see` and `handy see --window <title>` can now capture a single visible desktop window by title, app, or ID at 1:1 resolution while keeping global OS `(x, y)` coordinates on the rulers and grid badges.
- **Window-Relative Coordinate Space (`coordinateSpace: "window"`)**: Action steps in `handy_act` now accept `coordinateSpace: "window"`, offsetting `(x, y)` automatically relative to the active window's `{ x, y }` screen origin so scripts and reusable workflows stay accurate even if the user drags the window elsewhere on screen.
- **Pixel-Color Visual Synchronization (`wait_for_color`)**: New `wait_for_color` step in `handy_act` (and `wait_for_color <x> <y> <#rrggbb> [timeoutMs] [tolerance]` CLI shorthand) polls a tiny `3x3` patch around `(x, y)` and continues as soon as the pixel color matches within Euclidean RGB `tolerance` — ideal for waiting on status badges, loading spinners, or active button states.
- **Visual Diff Highlighting (`highlightDiff`)**: `handy_see`, `handy_act`, `handy see --highlight-diff`, and `handy ui` can draw a crisp emerald `CHANGED` bounding box around pixels modified since the previous frame.
- **Real-Time SSE Control Panel Push (`GET /api/events`)**: `handy ui` now streams live permission-state updates over Server-Sent Events (`EventSource`) whenever `handy on` / `handy off` / `handy toggle` or MCP changes permissions, updating the dashboard instantaneously without polling lag.
- **Per-Monitor Win32 DPI Scale Detection**: `Win32Backend` queries `MonitorFromPoint` + `GetDpiForMonitor` (`shcore.dll`) to report accurate per-monitor `scaleFactor` (`1.25x`, `1.5x`, `2.0x`) on multi-DPI Windows setups.
- **Expanded Slash Commands & Release Pipeline**: Added `/handy:doctor` and `/handy:windows` plugin slash commands, upgraded GitHub Actions CI to Node 24-native `actions/checkout@v7` + `actions/setup-node@v7`, and added `.github/workflows/release.yml` for tag-verified npm provenance publishing and GitHub Releases.

## [1.1.0] - 2026-11-12

### Added
- **Desktop Window Awareness & Focus (`handy_windows`, `focus_window`)**: List visible desktop windows with titles, owning apps, PIDs, and screen bounds `{ x, y, width, height }`, or bring a window to the foreground across Windows (`EnumWindows`/`SetForegroundWindow`), macOS (`CGWindowListCopyWindowInfo`/`NSRunningApplication`), Linux X11 (pure EWMH `_NET_CLIENT_LIST`/`_NET_ACTIVE_WINDOW` wire protocol), and Virtual Desktop.
- **Native Clipboard & Instant Paste (`handy_clipboard`, `paste`)**: Read/write Unicode clipboard text natively on Windows (MTA-safe Win32 `OpenClipboard`/`CF_UNICODETEXT`), macOS (`NSPasteboard`), Linux (`wl-clipboard`/`xclip`/`xsel`), and Virtual Desktop, plus a `paste` action step in `handy_act` with automatic clipboard preservation.
- **Smart Visual Synchronization (`wait_for_change`, `wait_for_settled`)**: Sub-2ms RGBA frame diffing lets chains wait until a UI region visibly updates or finishes animating instead of relying on fixed `wait` sleeps.
- **Richer Visual Perception (`handy_see`)**:
  - `pixelUnderMouse` (`#rrggbb` sampled from the raw unannotated frame before drawing the cursor reticle).
  - `activeWindow` metadata attached to `handy_see`, `handy_act`, and `handy_status`.
  - `screenDiff` (`changedPercent`, `changedPixels`, `changedBounds`) computed automatically between consecutive captures.
  - Dual-contrast coordinate grid lines (legible on both `#000000` dark and `#ffffff` light apps) and numbered amber **action-trail markers** (`#1`, `#2`, drag vectors) on `screenshotAfter` captures.
- **Physical Corner-Slam Failsafe**: Slamming the mouse cursor into the top-left `(0, 0)` corner aborts any active `handy_act` chain immediately and releases held inputs.
- **One-Command Host Installer (`handy install` / `handy uninstall`)**: Automatically registers or removes Handy in Claude Desktop, Cursor, Windsurf, and Claude Code with `--dry-run` and `.handy.bak` backups.
- **Local Live Control Panel (`handy ui`)**: Loopback (`127.0.0.1`) web dashboard with CSRF token protection, instant `ON` / `View Only` / `OFF` switches, live coordinate-mapped screen viewer, window switcher, and chain runner.
- **Faster Zero-Temp-File Captures**: In-memory CoreGraphics `CGWindowListCreateImage` PNG encoding on macOS (with `screencapture` fallback) and direct stdout PNG streaming for `grim`, `maim`, and `import` on Linux.

## [1.0.0] - 2026-11-12

### Added
- **Stdio MCP Server (`handy mcp`)**: Exposes `handy_see`, `handy_act`, `handy_status`, and `handy_permission`, plus `handy://status` and `handy://screen/current` resources and the `computer-control` workflow prompt.
- **Chained Real-Time Controls (`handy_act`)**: Execute sequential multi-step mouse and keyboard chains (move, click, double/triple/right click, drag, scroll, type, key chords, hold/release, wait, and mid/post-chain screenshots) in a single call with automatic held-input failsafe cleanup.
- **Coordinate-Mapped Screen Vision (`handy_see`)**: Real-time PNG screen capture annotated with exact OS screen coordinate rulers, interior `(x, y)` grid badges, `region` 1:1 zoom, and a high-contrast `MOUSE (x,y)` reticle.
- **Cross-Platform Native Backends**:
  - **Linux**: Pure native X11 wire-protocol backend (`XTEST` + `GetImage` + `BIG-REQUESTS` + `RANDR`, zero external packages required) plus Wayland/CLI backend (`grim`, `ydotool`, `wtype`, `xdotool`, `scrot`, `import`).
  - **macOS**: Persistent CoreGraphics JXA + `screencapture` backend with Retina logical-point coordinate mapping and Accessibility/Screen Recording diagnostics.
  - **Windows**: Persistent PowerShell + C# P/Invoke `SendInput` (`KEYEVENTF_UNICODE`, `MOUSEEVENTF_VIRTUALDESK`) and GDI `CopyFromScreen` backend with Per-Monitor V2 DPI awareness.
  - **Virtual**: Interactive `1280x800` virtual desktop (`HANDY_BACKEND=virtual`) for headless testing and CI.
- **Live Permission Toggle**: Atomic `~/.handy/permissions.json` on/off switch (`handy on`, `handy off`, `handy toggle`, `--view-only`, `--ttl`), enforced before every capture and every individual step in a chain.
- **Prepackaged Plugin & Skills**: Ships `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, `.mcp.json`, MCPB `manifest.json`, MCP Registry `server.json`, `skills/handy/SKILL.md`, and `/handy:on`, `/handy:off`, `/handy:toggle`, `/handy:status` commands.
